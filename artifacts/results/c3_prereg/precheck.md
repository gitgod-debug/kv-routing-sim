# POST HOC — would `kvsim calibrate`'s own cells have been enough? (C2's data, no GPU)

⚠️ Post hoc. C2 measured more cells than the command does. Here the cells the command would have measured are fitted with the command's own code, and C2's two held-out workloads are replayed with the result — the replay C2c was decided on. Run before C3 to choose the command's design. Generated by `scripts/c3_precheck.py`.

Decode cells: contexts 128, 512, 1024 × batches 1, 2, 4, 8, 16, one rep (C2's 128 stands in for the command's 32). Prefill cells: **cold only** = cold prompts of 64–1,984 tokens × 3, what the command measured until 2026-10-01; **with cached prefix** = those plus 64, 256 and 704 new tokens after 256, 768 and 1,280 cached ones × 3.

| prefill cells | decode rep | decode: base + per seq + per 1K context | prefill: base + per token + per token per 1K attended | K1_half p50 · p95 | K64_quarter p50 · p95 |
|---|---:|---|---|---|---|
| cold only | 0 | 40.9 ms + 0.25 + 3.43 | 20.8 ms + 0.239 + 0.842 | 1,855 ms (1.41×) · 13,238 ms (5.69×) | 451 ms (1.22×) · 1,952 ms (1.07×) |
| cold only | 1 | 41.9 ms + 0.00 + 3.64 | 20.0 ms + 0.239 + 0.842 | 2,059 ms (1.56×) · 16,711 ms (7.19×) | 460 ms (1.20×) · 2,029 ms (1.03×) |
| with cached prefix | 0 | 40.9 ms + 0.25 + 3.43 | 0.0 ms + 0.318 + 0.758 | 1,284 ms (1.03×) · 2,217 ms (1.05×) | 406 ms (1.36×) · 1,866 ms (1.12×) |
| with cached prefix | 1 | 41.9 ms + 0.00 + 3.64 | 0.0 ms + 0.317 + 0.758 | 1,375 ms (1.04×) · 2,804 ms (1.21×) | 422 ms (1.31×) · 1,890 ms (1.11×) |
| *C2's full fit (56 + 45 points)* | both | 40.1 ms + 0.34 + 3.50 | 0.0 ms + 0.319 + 0.758 | *1.10× · 1.41×* | *1.31× · 1.11×* |

Measured: K1_half 1,316 · 2,325 ms; K64_quarter 551 · 2,091 ms.

**Cold prompts alone are not enough.** Worst factor 7.19× — past C2c's 2× limit — against 1.36× with the cached-prefix cells. On a cold prompt the tokens attended to are always half the prompt, so cold cells measure only n and n², and two different splits describe them equally well: the cold-only fit has a lower per-token cost, an attention term 1.11× C2's, and a base that C2's fit does not have. Agentic traffic is the other case — a long cached prefix and few new tokens — and there the splits disagree: the cold-only fit charges 14% more prefill time on K1_half's requests (7% on K64_quarter's). K1_half sits at the knee of the load curve, where that much more service time becomes several times more queueing.

**What changed because of this:** since 2026-10-01 `kvsim calibrate` also times new tokens after a cached prefix (`--prefill-cached`, `--prefill-new`).
